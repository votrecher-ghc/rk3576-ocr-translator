## 1. 错误分级

| 等级   | 说明                 | 示例                             | 处理原则           |
| ------ | -------------------- | -------------------------------- | ------------------ |
| FATAL  | 系统无法继续运行     | 内核 panic、内存耗尽             | 重启系统           |
| ERROR  | 某模块不可用         | 驱动打开失败、RKNN 初始化失败    | 降级运行/重启模块  |
| WARN   | 异常但可继续         | 帧丢帧、传感器偶发读取失败       | 记录日志，继续运行 |
| INFO   | 正常事件记录         | 模式切换、配置变更               | 记录日志           |

## 2. 恢复策略

| 故障场景           | 检测方式         | 恢复策略                       |
| ------------------ | ---------------- | ------------------------------ |
| V4L2 DQBUF 超时    | 3s 超时          | STREAMOFF→STREAMON 重启采集    |
| RGA 处理失败       | 返回值检查       | 跳过该帧，记录日志             |
| RKNN 推理失败      | 返回值检查       | 重新加载模型，最多3次          |
| DRM PageFlip �败   | 返回值检查       | 重新设置 CRTC/Plane            |
| 传感器读取失败     | 连续3次失败      | 标记不可用，使用默认值         |
| 线程卡死           | 看门狗超时       | 重启该线程                     |

## 3. 降级方案

| 故障模块     | 降级行为                           |
| ------------ | ---------------------------------- |
| OCR 不可用   | 仅显示预览，不叠加翻译             |
| IMU 不可用   | 关闭电子防抖                       |
| 环境光不可用 | 使用固定屏幕亮度                   |
| 温度传感器   | 风扇全速运行                       |
| 翻译不可用   | 仅显示 OCR 原文                    |
| 内存不足     | 降低帧率，减少缓冲数量             |

## 4. 看门狗与自愈

### 4.1 软件看门狗

- 每个关键线程维护心跳计数器
- Main 线程每秒检查各线程心跳
- 超过 5s 无心跳则判定线程卡死，重启该线程

### 4.2 硬件看门狗

- 启用 RK3576 硬件看门狗（超时 30s）
- Main 线程定期喂狗
- 系统整体卡死时硬件看门狗触发复位

### 4.3 自愈流程

```
检测到故障 → 记录日志 → 评估是否可降级
  ├─ 可降级 → 切换降级模式 → 继续运行
  └─ 不可降级 → 重启模块/线程
        ├─ 重启成功 → 恢复运行
        └─ 重启失败(3次) → 重启系统
```

## 1. 系统定位

本系统是基于鲁班猫3 RK3576 开发板的**端侧 OCR 实时翻译终端**，核心定位：

- **全离线运行**：OCR 与翻译引擎完全部署在设备本地，无网络依赖
- **实时性强**：实时预览翻译端到端延迟 ≤ 300ms
- **零拷贝管线**：图像数据从采集到显示全程 DMA-BUF 共享，CPU 零搬运
- **异构算力**：A72/A53 CPU + Mali-G52 GPU + 6T NPU 协同工作
- **生产可用**：完整的驱动、构建、测试、部署体系

系统提供两种工作模式：
- **实时预览翻译模式**：摄像头持续取景，对画面文字实时 OCR 并叠加翻译结果
- **按键拍照翻译模式**：用户按键触发，对静态图像高精度 OCR 与翻译并归档

## 2. 硬件平台

### 2.1 SoC 架构

RK3576 采用 ARM big.LITTLE 异构架构，集成多种处理单元：

```
┌─────────────────────────────────────────────────┐
│                   RK3576 SoC                     │
├──────────────┬──────────────────────────────────┤
│  CPU Cluster │ 4× Cortex-A72 @2.2GHz (big)      │
│              │ 4× Cortex-A53 @1.8GHz (LITTLE)   │
├──────────────┼──────────────────────────────────┤
│  GPU         │ Mali-G52 MC3 (OpenGL ES/Vulkan)  │
├──────────────┼──────────────────────────────────┤
│  NPU         │ 6 TOPS @INT8                     │
├──────────────┼──────────────────────────────────┤
│  ISP         │ 4K HDR Image Signal Processor    │
├──────────────┼──────────────────────────────────┤
│  VPU         │ H.264/H.265/AV1 编解码 4K@60     │
├──────────────┼──────────────────────────────────┤
│  RGA         │ 2D 图形加速（缩放/旋转/格式转换） │
├──────────────┼──────────────────────────────────┤
│  Display     │ HDMI 2.1 / MIPI-DSI / RGB        │
├──────────────┼──────────────────────────────────┤
│  Camera IF   │ MIPI-CSI 4-lane ×2              │
└──────────────┴──────────────────────────────────┘
```

### 2.2 外设拓扑

```
                    ┌──────────┐
   IMX415 ─CSI-2──►│          │
   AP3216C ─I2C───►│  RK3576  │──HDMI──► 显示器
   ICM42688 ─SPI──►│          │──DSI───► LCD(可选)
   ADT7410 ─I2C───►│          │
   PWM风扇 ◄─PWM──│          │
   按键 ──GPIO───►│          │
                    └──────────┘
```

### 2.3 内存配置

| 项目       | 规格                  | 用途                           |
| ---------- | --------------------- | ------------------------------ |
| 物理内存   | 4GB LPDDR4X           | 系统运行 + DMA-BUF 缓冲池      |
| CMA 区域   | 256MB（预留）         | DMA-BUF 连续内存分配           |
| eMMC       | 32GB                  | 系统、应用、模型、归档数据     |
| Swap       | 不启用                | 避免 swap 影响实时性           |

### 3.2 各层职责

#### 3.2.1 硬件抽象层（HAL / Kernel）

| 组件             | 职责                                          |
| ---------------- | --------------------------------------------- |
| Linux 6.1 内核   | 提供 I2C/SPI/IRQ/clk/pinctrl/DMA 等基础子系统 |
| 设备树 (DTS)     | 描述硬件拓扑、引脚复用、外设配置               |
| CMA              | 连续内存分配，供 DMA-BUF 使用                  |

#### 3.2.2 驱动层（Driver Layer）

| 驱动             | 子系统    | 职责                                       |
| ---------------- | --------- | ------------------------------------------ |
| IMX415           | V4L2      | 摄像头采集驱动，通过 CSI/ISP 输出 NV12     |
| AP3216C          | IIO       | 环境光/距离传感器驱动，I2C 通信            |
| ICM42688         | IIO       | 六轴 IMU 驱动，SPI 通信                    |
| ADT7410          | IIO       | 高精度温度传感器驱动，I2C 通信             |
| PWM 风扇         | PWM/HWMon | PWM 调速 + hwmon 温度上报                  |
| 按键             | Input     | GPIO 按键，Input 事件上报                  |
| DRM/KMS          | DRM       | 显示控制器驱动，管理 CRTC/Plane/Connector  |
| RGA              | -         | 2D 图形加速驱动，用户态通过 librga 调用    |

#### 3.2.3 系统服务层（System Service Layer）

| 组件         | 职责                                          |
| ------------ | --------------------------------------------- |
| libdrm       | DRM/KMS 用户态库，显示输出与图层叠加          |
| librga       | RGA 用户态封装，图像缩放/旋转/格式转换        |
| rknn_api     | RKNN 模型推理接口，调用 NPU                   |
| libv4l       | V4L2 辅助库，摄像头缓冲管理                   |
| IIO sysfs    | 读取传感器数据（环境光/IMU/温度）             |
| Input evdev  | 读取按键事件                                  |
| sysfs/pwm    | PWM 风扇调速控制                              |

#### 3.2.4 核心业务层（Core Business Layer）

| 模块           | 职责                                                   |
| -------------- | ------------------------------------------------------ |
| pipeline       | 零拷贝管线管理，串联采集→处理→显示全链路              |
| ai (OCR+翻译)  | RKNN OCR 推理 + 离线翻译引擎                          |
| stab (EIS)     | 基于 IMU 数据的电子防抖                                |
| sensors/autoexp| 环境光自适应亮度控制                                   |
| display        | DRM/KMS 显示与 OSD 翻译结果叠加                        |
| capture        | 按键拍照与图像捕获                                     |
| archive        | 翻译结果归档存储                                       |
| thermal        | 温度监测与 PWM 风扇调速                                |

#### 3.2.5 应用控制层（Application Layer）

| 模块       | 职责                                           |
| ---------- | ---------------------------------------------- |
| 主控       | 系统启动、模式切换、生命周期管理                |
| input      | 按键事件分发                                    |
| comm       | 进程间通信与配置管理                            |

│                                                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐       │
│  │ OCR推理  │  │ 翻译线程  │  │ IMU采集  │  │ 环境光   │       │
│  │ 线程     │  │          │  │ 线程     │  │ 线程     │       │

│                                                                │
│  ┌──────────┐  ┌──────────┐                                  │

### 4.2 线程职责概要

| 线程         | CPU 亲和 | 优先级 | 职责                             |
| ------------ | -------- | ------ | -------------------------------- |
| Main         | A72      | 普通   | 模式管理、生命周期               |
| V4L2 Capture | A53      | 高     | 摄像头帧采集                     |
| DRM Display  | A53      | 高     | 显示输出与 VSync 同步            |
| RGA Process  | A53      | 高     | 图像格式转换与缩放               |
| OCR Inference| A72      | 高     | RKNN 模型推理（NPU）            |
| Translate    | A72      | 普通   | 翻译引擎                         |
| IMU Sensor   | A53      | 普通   | ICM42688 数据采集（EIS）        |
| Light Sensor | A53      | 低     | AP3216C 环境光采集               |
| Thermal      | A53      | 低     | ADT7410 温度监测与风扇控制       |
| Input        | A53      | 普通   | 按键事件监听                     |

> 详细的线程模型见 [04-线程与并发模型.md](04-线程与并发模型.md)

### 4.3 实时模式数据流

```
IMX415 → CSI → ISP → V4L2(DMA-BUF)
                           │
                           ├─→ RGA(缩放/格式) → DRM Plane0(视频层) → 显示
                           │
                           └─→ RGA(预处理) → RKNN(OCR) → 文本
                                                    │
                                                    └→ 翻译 → OSD文本 → DRM Plane1(OSD层) → 叠加显示
                                          │
                          IMU → EIS补偿 ──┘
                          环境光 → 背光调节 ─→ 屏幕亮度
```

### 4.4 拍照模式数据流

```
按键事件 → Main切换至拍照模式
                │
                ├─→ V4L2 获取高分辨率帧(DMA-BUF)
                │         │
                │         └─→ RGA(预处理) → RKNN(OCR高精度) → 文本
                │                                          │
                │                                          └→ 翻译
                │
                ├─→ 合成翻译结果图 → 归档存储(JPG+TXT)
                │
                └─→ 恢复实时预览模式
```

## 6. 关键设计决策

### 6.1 决策一：零拷贝管线

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 决策     | 采用 V4L2 → DMA-BUF → RGA → DRM 全链路零拷贝                |
| 理由     | RK3576 内存带宽有限，CPU 搬运 4K 图像开销过大；零拷贝可降低 CPU 占用 80%+ |
| 代价     | 需统一各环节的缓冲格式与 fd 传递机制，开发复杂度增加         |
| 替代方案 | 用户态 malloc + memcpy（简单但性能差，已否决）               |

### 6.2 决策二：NPU 专用 OCR

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 决策     | OCR 推理使用 NPU（RKNN），不使用 CPU                         |
| 理由     | NPU INT8 算力 6TOPS，OCR 模型推理仅需 ~20ms；CPU 推理需 200ms+ |
| 代价     | 模型需量化转换，精度略有损失                                 |
| 替代方案 | CPU 推理（延迟过高，已否决）                                 |

### 6.3 决策三：DRM/KMS 而非 framebuffer

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 决策     | 显示采用 DRM/KMS，不使用传统 framebuffer                     |
| 理由     | DRM/KMS 支持多 Plane 叠加、VSync 同步、DMA-BUF 直接导入，适合零拷贝 |
| 代价     | API 较复杂，需熟悉 KMS 概念                                  |
| 替代方案 | /dev/fb（功能弱，不支持硬件叠加，已否决）                    |

### 6.4 决策四：单进程多线程

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 决策     | 单进程多线程架构，不采用多进程                               |
| 理由     | 线程间共享 DMA-BUF fd 更简单；避免 IPC 开销；减少内存拷贝   |
| 代价     | 线程间需精细同步；单点崩溃影响全局                           |
| 替代方案 | 多进程 + 共享内存（复杂度高，已否决）                        |

### 6.5 决策五：IIO 子系统管理传感器

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 决策     | AP3216C/ICM42688/ADT7410 统一使用 IIO 子系统                 |
| 理由     | IIO 是 Linux 传感器标准子系统，用户空间通过 sysfs/buffer 统一访问 |
| 代价     | 需遵循 IIO 框架开发驱动                                      |
| 替代方案 | 自定义字符设备驱动（不标准，已否决）                         |

### 6.6 决策六：电子防抖基于 IMU

| 项目     | 内容                                                         |
| -------- | ------------------------------------------------------------ |
| 决策     | 使用 ICM42688 IMU 数据实现软件电子防抖（EIS）               |
| 理由     | IMU 采样率高（8kHz），可实时补偿手抖；纯算法防抖效果有限     |
| 代价     | 需 IMU 与 V4L2 帧时间戳对齐；增加 RGA 变换计算               |
| 替代方案 | 纯算法防抖（效果差，已否决）                                 |

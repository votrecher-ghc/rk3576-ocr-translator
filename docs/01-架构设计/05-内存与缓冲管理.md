## 1. 内存预算

### 1.1 总体内存分配（4GB LPDDR4X）

| 用途               | 大小     | 说明                       |
| ------------------ | -------- | -------------------------- |
| Linux 内核         | 64MB     | 内核镜像 + 运行时          |
| CMA 区域           | 256MB    | DMA-BUF 连续内存           |
| 应用程序代码+数据  | 128MB    | 主程序 + 库                |
| RKNN 模型          | 128MB    | OCR/翻译模型加载           |
| V4L2 采集缓冲池    | 96MB     | 4帧 4K NV12                |
| RGA 处理缓冲       | 32MB     | 中间格式转换               |
| DRM 显示缓冲       | 32MB     | 双缓冲 1080p               |
| OSD 叠加缓冲       | 16MB     | ARGB8888                   |
| 翻译引擎           | 128MB    | 词典+工作内存              |
| 系统其他           | 64MB     | 栈/堆/碎片                 |
| **合计**           | **~1GB** | 剩余 ~3GB 供页缓存等使用   |

### 1.2 内存约束

- 不启用 swap（保证实时性）
- 使用 `mlockall` 锁定关键内存页
- 模型与词典使用 mmap 映射，不复制

## 2. CMA 配置

### 2.1 内核 CMA 配置

```dts
// reserved-memory 节点
reserved-memory {
    #address-cells = <2>;
    #size-cells = <2>;
    ranges;

    cma_region: linux,cma {
        compatible = "shared-dma-pool";
        size = <0x0 0x10000000>;  /* 256MB */
        reusable;
        linux,cma-default;
    };
};
```

### 2.2 内核配置

```
CONFIG_CMA=y
CONFIG_CMA_AREAS=7
CONFIG_DMA_CMA=y
CONFIG_CMA_SIZE_MBYTES=256
```

## 3. DMA-BUF 缓冲池设计

### 3.1 缓冲池结构

```c
typedef struct dma_buf_pool {
    int count;                  // 缓冲数量
    int buf_size;               // 单缓冲大小
    dma_buf_t *bufs;            // 缓冲数组
    sem_t free_sem;             // 空闲缓冲信号量
    pthread_mutex_t lock;       // 保护空闲链表
    int free_list[MAX_BUFS];    // 空闲缓冲索引
    int free_count;
} dma_buf_pool_t;

typedef struct dma_buf {
    int fd;                     // DMA-BUF 文件描述符
    void *mapped;               // mmap 映射地址
    size_t size;                // 缓冲大小
    int width, height;          // 图像尺寸
    uint32_t format;            // 像素格式
    atomic_t refcount;          // 引用计数
} dma_buf_t;
```

### 3.2 缓冲池规格

| 缓冲池         | 数量 | 单帧大小 | 用途                 |
| -------------- | ---- | -------- | -------------------- |
| V4L2 采集池    | 4    | 8MB(4K)  | 摄像头采集           |
| RGA 显示池     | 3    | 6MB(1080p)| 显示用              |
| RGA OCR 池     | 3    | 2MB      | OCR 输入预处理       |
| OSD 缓冲       | 2    | 8MB      | 翻译结果叠加         |

### 3.3 缓冲分配流程

```
申请: pool_acquire() → 等待free_sem → 取空闲缓冲 → refcount=1 → 返回
释放: pool_release() → refcount-- → 若refcount==0 → 归还空闲链表 → post free_sem
```

## 4. 引用计数管理

### 4.1 引用计数设计

DMA-BUF 使用原子引用计数，支持多模块共享同一缓冲：

```c
// 获取引用
dma_buf_t *dma_buf_get(dma_buf_t *buf) {
    atomic_inc(&buf->refcount);
    return buf;
}

// 释放引用
void dma_buf_put(dma_buf_t *buf) {
    if (atomic_dec_and_test(&buf->refcount)) {
        // 引用归零，归还缓冲池
        pool_release(buf);
    }
}
```

### 4.2 典型引用场景

```
V4L2采集帧: refcount=2
  ├─ RGA显示路 (持有1份)
  └─ RGA OCR路 (持有1份)
各自处理完毕后 dma_buf_put
```

## 5. 内存生命周期

### 5.1 缓冲生命周期

```
系统启动
  │
  ├─ pool_init() → 分配DMA-BUF (CMA)
  │
  ├─ 运行期: acquire → 使用 → release (循环)
  │
  └─ 系统退出
      └─ pool_destroy() → 释放DMA-BUF
```

### 5.2 内存泄漏防护

- 每个缓冲池维护 `acquired_count`，定期校验
- 退出时检查所有缓冲已归还
- 使用 valgrind（用户态部分）定期检测

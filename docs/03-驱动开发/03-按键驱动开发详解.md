# 按键驱动开发详解

| 版本 | 日期 | 作者 | 变更说明 |
|---|---|---|---|
| v1.0 | 2026-07-10 | 项目组 | 初始版本 |
| v2.0 | 2026-07-16 | 项目组 | 对齐自研 `ocr,gpio-keys` 驱动与 `KEY_CAMERA` 发现机制 |

---

## 1. 当前实现

本项目没有使用旧文档中的通用 `gpio-keys + KEY_ENTER` 方案，而是提供：

- 内核驱动：`bsp/kernel/drivers/gpio_keys_ocr.c`
- overlay：`bsp/kernel/arch/arm64/boot/dts/rockchip/overlays/gpio-keys.dtso`
- 用户态监听：`app/input/key_event.c`

当前 overlay 候选值为 GPIO0_PC0、低电平有效、20ms 消抖和 `KEY_CAMERA`。GPIO 与
物理 40Pin 的映射尚未实板确认，不能直接视为最终接线结论。

## 2. DTS 契约

```dts
ocr_gpio_keys: ocr-gpio-keys {
    compatible = "ocr,gpio-keys";
    label = "ocr-camera-key";
    gpios = <&gpio0 16 GPIO_ACTIVE_LOW>;
    linux,code = <KEY_CAMERA>;
    debounce-interval = <20>;
    status = "okay";
};
```

必须核对：

- `gpio0` 与 pin 16 是否对应目标物理引脚；
- 该引脚是否已被其他节点占用；
- pinctrl 和内部上拉；
- active-low 极性；
- 按键电路是否需要外部上拉或 RC 去抖。

## 3. 内核驱动流程

`gpio_keys_ocr.c` 的主要流程：

1. 解析 `gpios`、`linux,code`、`debounce-interval` 和 `label`；
2. 申请 GPIO 并设置为输入；
3. 分配并注册 Input 设备；
4. 同时申请上升沿和下降沿 IRQ；
5. IRQ 中只重启消抖 timer；
6. timer 到期后重新读取 GPIO；
7. 状态变化时上报 `EV_KEY / KEY_CAMERA` 并调用 `input_sync()`；
8. suspend/resume 和 remove 阶段停止 timer、释放状态。

用户态依赖的是 Input capability，不依赖内核分配的事件编号。

## 4. 用户态发现

`app/input/key_event.c` 会枚举 `/dev/input/event*`，查询：

- 是否支持 `EV_KEY`；
- 是否支持 `KEY_CAMERA`。

只有唯一匹配时才启动监听；零个或多个匹配都会明确失败，避免误监听其他按键设备。

## 5. 板端验证

```bash
cat /proc/bus/input/devices

KEY_EVENT="$(
    for e in /dev/input/event*; do
        evtest --query "$e" EV_KEY KEY_CAMERA >/dev/null 2>&1 &&
            printf '%s\n' "$e"
    done
)"
[ -n "$KEY_EVENT" ] || exit 1
evtest "$KEY_EVENT"
```

验收要求：

- 只能发现一个 `KEY_CAMERA` 设备；
- 每次按下和释放各上报一次；
- 无机械抖动造成的重复事件；
- 长按不会被错误识别为多次拍照，除非产品明确要求重复触发；
- 应用退出时按键线程可以及时停止；
- 人为移除/关闭 input 设备后，应用记录工作线程错误并退出或降级。

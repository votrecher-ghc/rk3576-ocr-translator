## 1. 项目背景

### 1.1 行业背景

随着全球化进程加速和跨境交流日益频繁，实时翻译设备在教育、旅游、商务、工业巡检等场景的需求持续增长。传统翻译设备依赖云端算力，存在网络依赖、延迟高、隐私泄露等问题。端侧 AI 推理技术的发展使得在嵌入式设备上完成"图像采集 → 文字识别 → 翻译 → 显示"全流程成为可能。

### 1.2 项目定位

本项目基于鲁班猫3（LubanCat 3）RK3576 开发板，构建一套**端侧 OCR 实时翻译系统**。系统无需联网即可完成图像采集、文字识别、多语言翻译和实时显示，适用于离线、低延迟、隐私敏感的应用场景。

### 1.3 硬件来源

鲁班猫3 是野火（EmbedFire）推出的基于瑞芯微 RK3576 SoC 的开发板，具备较强的异构计算能力（A72 + A53 + Mali-G52 + 6T NPU），适合边缘 AI 应用。本项目在此基础上扩展摄像头、环境光传感器、IMU、温度传感器、PWM 风扇和按键，构成完整的翻译终端。

## 2. 项目目标

### 2.1 核心目标

| 目标项       | 指标要求                                   |
| ------------ | ------------------------------------------ |
| 实时翻译延迟 | 端到端 ≤ 300ms（采集到显示）               |
| OCR 准确率   | 印刷体中文/英文 ≥ 95%                      |
| 翻译语言     | 至少支持中英双向翻译                       |
| 离线运行     | 全流程无需联网                             |
| 显示帧率     | 实时预览 ≥ 30fps                           |
| 功耗         | 典型场景 ≤ 5W                              |

### 2.2 技术目标

- **零拷贝图像管线**：通过 V4L2 → DMA-BUF → RGA → DRM/KMS 实现图像数据全程零拷贝，最大化降低 CPU 开销和内存带宽占用
- **异构算力利用**：合理分配 A72/A53 CPU、Mali-G52 GPU、6T NPU 的计算任务
- **驱动完整**：为所有外设编写完整的 Linux 驱动，符合内核子系统规范
- **生产可用**：提供完整的构建、部署、运维、测试方案

## 3. 功能列表

### 3.1 核心功能

| 编号  | 功能名称         | 描述                                                   |
| ----- | ---------------- | ------------------------------------------------------ |
| F-001 | 实时预览翻译     | 摄像头实时取景，对画面中文字进行 OCR 识别并叠加翻译结果 |
| F-002 | 按键拍照翻译     | 按键触发拍照，对静态图像进行高精度 OCR 与翻译并归档     |
| F-003 | 离线翻译引擎     | 基于离线模型的机器翻译，支持中英双向                   |
| F-004 | 翻译结果叠加显示 | 使用 DRM/KMS 图层叠加翻译结果到预览画面                |

### 3.2 辅助功能

| 编号  | 功能名称         | 描述                                                 |
| ----- | ---------------- | ---------------------------------------------------- |
| F-005 | 电子防抖（EIS）  | 基于 IMU 数据的软件电子防抖，提升预览和拍照稳定性    |
| F-006 | 自适应亮度       | 根据 AP3216C 环境光数据自动调节屏幕显示亮度          |
| F-007 | 温度监测与散热   | 通过 ADT7410 监测温度，PWM 自动调节风扇转速          |
| F-008 | 翻译结果归档     | 拍照翻译结果保存为图片+文本，支持本地回看            |
| F-009 | 异常恢复         | 驱动异常、内存不足等场景的自动降级与恢复             |

## 6. 系统特性概览

### 6.1 零拷贝管线

系统采用全链路零拷贝设计，图像数据从摄像头采集到屏幕显示全程以 DMA-BUF 形式流转，仅在 AI 推理环节做必要格式转换：

```
IMX415 → CSI → ISP → V4L2(DMA-BUF) → RGA(缩放/格式) → DRM/KMS(显示)
                                  └→ RKNN(OCR) → 翻译 → OSD叠加
```

### 6.2 异构计算分配

| 计算单元   | 任务                                   |
| ---------- | -------------------------------------- |
| A72 (大核) | AI 推理调度、翻译引擎、主控制逻辑      |
| A53 (小核) | 传感器轮询、日志、系统服务             |
| Mali-G52   | 图像格式转换辅助（可选）               |
| NPU        | OCR 模型推理（文字检测 + 识别）        |
| RGA        | 图像缩放、旋转、格式转换（硬件加速）   |

### 6.3 实时性保障

- V4L2 采集与 DRM 显示使用独立高优先级线程
- AI 推理线程绑定至 A72 大核
- 传感器线程绑定至 A53 小核，避免干扰主链路
- 预分配 DMA-BUF 缓冲池，避免运行时内存分配

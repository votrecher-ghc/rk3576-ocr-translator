## 1. 当前实现边界

应用通过 ADT7410 读取温度，并以 25kHz PWM 控制四档风扇：

| 温度范围 | 目标档位 | 占空比 |
|---|---:|---:|
| `< 45°C` | 0 | 0% |
| `45–55°C` | 1 | 25% |
| `55–65°C` | 2 | 50% |
| `65–75°C` | 3 | 75% |
| `>= 75°C` | 4 | 100% |

降档阈值分别为 42/52/62/72°C，相当于 3°C 回差。

当前实现不会主动修改 NPU/CPU 频率，也不会自动关机。温度设备缺失或读取失败时，
应用将风扇切到 100% 并记录错误。若产品需要 thermal throttling 或 shutdown，必须
结合 vendor thermal framework、器件额定值和数据一致性策略另行设计与验收。

## 2. 功耗数据

仓库目前没有经过校准仪器和固定测试条件得到的功耗结果。不要使用旧文档中的
1.5W/3.5W/5W 估算作为规格。

板端测试至少记录：

| 场景 | 必须固定的条件 |
|---|---|
| 空闲预览 | 分辨率、FPS、背光、NPU 是否运行、风扇档位 |
| 实时 OCR/翻译 | 模型版本、文本框数量、输入分辨率、CPU fallback |
| 拍照翻译 | JPEG 路径、输入尺寸、一次会话持续时间 |
| 长稳 | 环境温度、供电电压、持续时间、风扇曲线 |

建议同时记录平均功耗、峰值功耗、SoC/板载温度、FPS 和 P95 延迟。

## 3. 运维检查

```bash
# ADT7410
TEMP="$(
    for d in /sys/bus/iio/devices/iio:device*; do
        [ "$(cat "$d/name" 2>/dev/null)" = adt7410 ] && printf '%s\n' "$d"
    done
)"
[ -n "$TEMP" ] || exit 1
cat "$TEMP/in_temp_input"

# CPU 频率
for f in /sys/devices/system/cpu/cpu*/cpufreq/scaling_cur_freq; do
    [ -r "$f" ] && printf '%s: ' "$f" && cat "$f"
done

# 应用风扇日志
grep -Ei 'fan|风扇|温度|PWM' /var/log/ocr_translator.log
```

不要在应用运行时手工 export 或写 PWM sysfs；应用持有独占进程锁，手工操作会破坏
所有权和退出恢复语义。

## 4. 运维建议

- 定期检查风扇是否可靠启转，并清理灰尘；
- 确认进风与出风路径没有遮挡；
- 记录温度趋势和风扇档位变化；
- 温度传感器故障时确认风扇已经进入满速；
- PWM 写入或 cleanup 失败时停止长期运行并检查 wiring/driver；
- 环境温度上限和自动停机阈值应由实测及产品安全要求确定。

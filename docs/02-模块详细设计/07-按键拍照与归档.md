## 1. 概述

实时预览翻译始终运行，没有单独的拍照模式。按键随时可以按：程序把下一次实时识别完成的那一帧，连同它的原文和译文一起存档。拍照不另做推理，RKNN 模型只由实时 OCR 线程使用，不需要跨线程加锁。

## 2. 拍照流程

```
按键线程: KEY_CAMERA 按下 → ocr_capture_session_request()   // 只置一个原子标记，立即返回

OCR 线程: ocr_process()
  → 检测 → 识别 → 逐框翻译
  → publish_overlay()                          // 结果先交给屏幕文字层
  → ocr_capture_session_take_request() == 1 ?  // 识别成功后才取走请求
      → ocr_capture_session_save()             // 画面叠加译文 → JPEG，写 txt/json
      → 屏幕左下角提示“已保存”/“保存失败”约 2 秒
  → 结束 CPU 读同步
```

| 按键时 OCR 的状态 | 存下的帧 | 按键后多久完成 |
| ----------------- | -------- | -------------- |
| 正在识别 | 正在识别的这一帧 | 不超过一轮识别 |
| 空闲 | 下一帧 | 最多一帧间隔 + 一轮识别 |

- 识别失败时请求保留，存下一帧；没检测到文字照常存档，结果为空。
- 一轮识别期间的多次按键合并为一张。
- 存档期间 OCR 线程持有这块输出缓冲，屏幕照常换帧，内容不会被覆盖。
- 按键设备缺失、打开失败或运行中退出，以及归档目录不可用，都只禁用拍照，实时预览照常运行。

## 3. 结果合成

- 画面是实时识别用的 RGA 输出：显示分辨率（默认 1280×720），经过防抖裁剪。
- 译文与屏幕文字层用同一套渲染代码（`display/text_renderer`）、同一字体字号、颜色和位置：有译文画译文，翻译失败画原文，起点为检测框左上角。
- 文字先画到透明 premultiplied ARGB 图层，编码 JPEG 时逐行按 `out = 文字 + 画面 × (1 − α)` 叠加，与显示控制器的混合方式一致。
- 拍照会话持有独立的 FreeType 实例；字体加载失败时照片不带译文，其余内容照常保存。

## 4. 归档存储

```
<archive.base_dir>/YYYYMMDD/HHMMSS_mmm_<pid>_<序号>/
├── image.jpg      // 叠加译文的画面
├── result.txt     // 原文 + 译文
└── result.json    // 时间、语言、每个框的坐标/置信度/原文/译文
```

- 主循环每秒检查一次容量，超过 `archive.max_usage_pct` 时从最旧的日期目录开始删除，不删当天目录。
